# お遍路みちしるべ 品質改善仕様書

## 1. 目的

現在の機能・画面デザイン・Android WebViewでの動作を維持しながら、次の4点を改善する。

1. TypeScriptの型チェックを正常化する
2. 重要ロジックの自動テストを追加する
3. 巨大な `src/public/index.html` を段階的に分割する
4. Gitリポジトリと配信画像を軽量化する

本作業は全面的な作り直しではない。小さな単位で変更し、各段階で既存動作を確認する。

## 2. 対象外

- `DISABLE_GOSHUIN_LOCATION_CHECK = true` は、現在テスト目的で意図的に設定されているため変更しない。
- UIデザイン、御朱印画像そのもの、ルート計算仕様、位置判定距離は変更しない。
- React、Vue等のフレームワークへの移行は行わない。
- データベースの本番設定やCORS等のセキュリティ対応は、この仕様書の対象外とする。

## 3. 共通作業ルール

- 必ず最新の `origin/main` を取得し、そこから `codex/quality-improvements` ブランチを作成する。
- 利用者の確認を容易にするため、原則として後述のフェーズごとにコミットを分ける。
- 既存の関数名、DOMのID、CSSクラス、`localStorage` のキー、APIの入出力形式は、必要がない限り変更しない。
- Android WebView、スマートフォンChrome、PCブラウザの3環境を意識する。
- 見た目の変更を目的としない。分割前後の画面差分が出ないことを優先する。
- 御朱印の取得状態や設定値など、既存の保存データを消さない。

---

## 4. フェーズ1：TypeScript型チェックの正常化

### 現状

`npx tsc --noEmit` を実行すると、TypeScript 7と `moduleResolution: "node"` の組み合わせにより `TS5108` が発生する。

### 実装方針

今回は設定全体への影響を抑えるため、TypeScriptを安定版の5.9系へ固定する。

1. `package.json` の `typescript` を厳密なバージョン `5.9.3` に変更する。
2. `package-lock.json` を更新する。
3. `package.json` に以下のスクリプトを追加する。

```json
"typecheck": "tsc --noEmit"
```

4. `npm run typecheck` で新たな型エラーが出た場合は、動作を変えずに型だけを修正する。
5. エラー回避のために `strict: false` や広範囲な `any` を追加しない。

### 完了条件

- `npm ci` が成功する。
- `npm run typecheck` が警告ではなく終了コード0で完了する。
- `npm start` でサーバーが起動する。

## 5. フェーズ2：自動テストの追加

### 使用ツール

- テストランナーは `Vitest` を使用する。
- DOMが必要なテストだけ `jsdom` を使用する。
- 最初から画面全体の自動操作テストは導入せず、壊れやすい計算処理を優先する。

### package.jsonへ追加するスクリプト

```json
"test": "vitest run",
"test:watch": "vitest",
"typecheck": "tsc --noEmit",
"check": "npm run typecheck && npm test"
```

### 優先してテストする対象

1. 西暦から和暦・漢数字への変換
   - 一、十、十一、二十、三十一を含む日付
   - 令和元年
   - 月末・年末
2. 札所と現在地の距離計算
   - 同一地点
   - 100m未満
   - 100～200m
   - 200m超
   - 位置精度が不正な場合
3. 納経時間に関する表示
   - 59分
   - 60分
   - 61分
   - 120分以上
4. 距離表示
   - 999m
   - 1000m
   - 1500mをkm表示する場合
5. バス時刻・運行日判定
   - 通常ダイヤ
   - 日付をまたぐ時刻
   - `calendar_dates` の運休・臨時運行
6. 多言語辞書
   - 必須キーが全対応言語に存在すること
   - 言語切り替え後に未翻訳キーがそのまま表示されないこと

### 実装上の注意

- `index.html` 内の純粋な計算処理を、先に副作用のない関数としてJSファイルへ切り出してからテストする。
- Google Maps、位置情報、ネットワーク通信は直接呼ばず、テスト時は置き換え可能にする。
- 現在意図的に無効化している御朱印位置制限を、テストの都合で有効化しない。

### 最初の完了基準

- 最低20件のテストを追加する。
- `npm test` が終了コード0になる。
- `npm run check` が成功する。
- 上記の重要ロジックに対するテストを優先し、数値だけを目的とした無意味なテストを作らない。

## 6. フェーズ3：index.htmlの段階的な分割

### 目的

約4,000行ある `src/public/index.html` を、機能別に追いやすい構成へ変更する。ただし、画面と動作は変更しない。

### 推奨構成

```text
src/public/
  index.html
  css/
    base.css
    layout.css
    components.css
    map.css
    goshuin.css
    themes.css
  js/
    constants.js
    i18n.js
    storage.js
    date-utils.js
    geo-utils.js
    settings.js
    goshuin.js
    map.js
    route-planner.js
    app.js
```

### 分割順序

1. CSSを、内容を変更せずそのまま外部ファイルへ移す。
2. 定数・翻訳辞書を `constants.js` と `i18n.js` へ移す。
3. 和暦・距離等の純粋関数を `date-utils.js` と `geo-utils.js` へ移す。
4. 設定、御朱印、地図、ルート計算の順で分割する。
5. 最後に起動処理だけを `app.js` に残す。

### 互換性方針

- 初回の分割ではES Modulesへ一気に移行せず、従来の `<script defer>` と `window.OhenroApp` 名前空間を使用してもよい。
- Android WebViewや `file://` 読み込みで問題が出ない方式を優先する。
- HTML内の `onclick` 等から参照される関数は、分割後も同じ名前で呼び出せるようにする。
- スクリプトの読み込み順を明示し、依存するファイルより先に共通処理を読み込む。
- CSSの詳細度と読み込み順を維持し、ライト・ダーク・自動テーマすべてで表示を比較する。

### 各分割後の確認項目

- ホームのルート計算
- 現在地からの自動設定
- 地図表示、現在地、コンパス、回転
- 徒歩・バス経路の切り替え
- 納経時間と天気表示
- 御朱印一覧・詳細・訪問日の表示
- 日本語を含む全言語の切り替え
- ライト・ダーク・自動テーマ
- Androidの戻る操作と画面下部ナビゲーション
- 既存の `localStorage` データの引き継ぎ

### 完了条件

- `index.html` は主にHTML構造と外部ファイル読込だけになっている。
- 画面の見た目と操作結果が分割前と一致する。
- `npm run check` が成功する。
- ブラウザとAndroid実機の主要操作確認が完了する。

## 7. フェーズ4：Git管理と配信容量の軽量化

### 7.1 node_modules

`.gitignore` には既に `node_modules/` があるが、過去に登録されたファイルが追跡対象に残っている。

```powershell
git rm -r --cached node_modules
```

この操作はGitの追跡だけを外し、ローカルの `node_modules` は削除しない。以降は `npm ci` で再現する。

### 7.2 downloads

`downloads/` も `.gitignore` の対象だが、GTFS ZIPが追跡されている。原則としてZIP本体はGit管理から外す。

```powershell
git rm -r --cached downloads
```

代わりにREADMEへ以下を残す。

- データ提供元URL
- 対応する `agency_key`
- 取得日または更新確認方法
- インポートコマンド
- ライセンスとクレジット

Railway等の本番DBへ既に取り込まれたデータを削除しないよう注意する。この作業はGit上のZIPを外すだけであり、DB削除処理は行わない。

### 7.3 御朱印画像

88枚の見た目を変えず、Web配信用画像をWebPへ変換する。

- 元画像は別途バックアップしてから作業する。
- 縦横比と日付記入位置を維持する。
- 推奨サイズは現在の画面表示に必要な最大解像度を基準とし、過剰な解像度を避ける。
- WebP品質は最初に85前後で比較し、筆文字・朱印・和紙の質感が崩れる場合は上げる。
- 目標は1枚500KB程度以下。ただし画質を優先し、一律に強く圧縮しない。
- まず3枚だけ変換し、PC・Android実機・御朱印一覧・詳細画面で比較してから88枚へ展開する。
- ファイル拡張子を変える場合は、画像パス生成処理とフォールバック表示も更新する。
- PNGからWebPへ移行後、参照されなくなったPNGだけを削除する。

### 7.4 Git履歴

通常の削除コミットでは、過去履歴に含まれる大容量ファイルまでは消えない。ただし、最初の対応では履歴を書き換えない。

`git filter-repo` 等による履歴削除は、既存ブランチや他端末へ影響するため別作業とし、明示的な承認を得てから実施する。

### 完了条件

- `node_modules/` と `downloads/` が新しいコミットへ再登録されない。
- 新規環境で `npm ci` から起動できる。
- 御朱印88枚が一覧・詳細画面ですべて表示できる。
- 日付の重ね表示が従来と同じ位置・字体で表示される。
- 初期表示および御朱印一覧の読み込みが悪化していない。

## 8. 推奨コミット単位

1. `chore: TypeScriptを安定版へ固定し型チェックを追加`
2. `test: 日付・距離・運行判定の自動テストを追加`
3. `refactor: index.htmlからCSSを分割`
4. `refactor: 共通処理と画面機能のJavaScriptを分割`
5. `chore: node_modulesとGTFS ZIPをGit管理から除外`
6. `perf: 御朱印画像をWeb向けに最適化`

各コミットで `npm run check` を実行し、画面分割以降は主要画面の手動確認結果もPR本文へ記載する。

## 9. 最終受け入れ条件

- `npm ci`、`npm run typecheck`、`npm test` がすべて成功する。
- 既存のホーム、地図、ルート結果、御朱印、設定、多言語、テーマ機能が動作する。
- Android実機で現在地・コンパス・画面遷移を確認できる。
- 御朱印のテスト用位置判定無効化は維持されている。
- 既存利用者の保存データが引き継がれる。
- `node_modules` とGTFS ZIPがGitの追跡対象から外れている。
- 変更内容、確認環境、既知の未対応事項がPR本文に記録されている。
