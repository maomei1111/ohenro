# 気象庁天気予報への移行仕様

## 1. 目的

ルート結果に表示する天気情報を Open-Meteo から気象庁発表の予報へ移行する。

移行後に表示する項目は次の3項目だけとする。

- 天気
- 気温
- 降水確率

湿度は表示しない。

この変更の目的は、日本国内で一般に参照される気象庁予報と表示内容を揃え、外部サービスの無料リクエスト上限による取得エラーをなくすことである。

## 2. 基本方針

- 気象庁が公開する防災情報XMLをサーバー側で取得する。
- 気象庁Webサイトの画面や、公開仕様が保証されていない内部JSONをスクレイピングしない。
- ブラウザやAndroid WebViewから気象庁へ直接アクセスしない。
- 札所ごとに、対応する気象庁の予報区域と気温観測・予報地点をあらかじめ割り当てる。
- 気象庁へのアクセスはサーバー側キャッシュで集約し、ユーザー数やルート内の札所数に比例して増加させない。
- 取得失敗時に、別会社の予報値へ自動的に切り替えない。古い値を最新値のように表示することもしない。

## 3. 使用する気象庁データ

### 3.1 今日から明後日まで

府県天気予報のXML電文を使用する。

- データ種類コード: `VPFD51`
- 主な利用項目: 天気、降水確率、最高・最低気温
- 発表頻度: 原則1日3回および随時更新

降水確率は、電文に時間帯別の値がある場合、札所への到着予定時刻を含む時間帯の値を採用する。

### 3.2 それより先から7日先まで

府県週間天気予報のXML電文を使用する。

- データ種類コード: `VPFW50`
- 主な利用項目: 日別の天気、降水確率、最高・最低気温
- 発表頻度: 原則1日2回

週間予報は日単位のため、到着予定時刻によらず、その日の値を表示する。

### 3.3 予報範囲外

気象庁の予報期間を超える日付については、天気欄を表示しない。推測値や固定値は表示しない。

## 4. 札所と予報区域の対応

`src/data` 配下に、札所番号と気象庁区域を対応付けるJSONを追加する。

各札所について最低限、次の情報を保持する。

```json
{
  "templeNo": 1,
  "forecastOfficeCode": "気象台コード",
  "forecastAreaCode": "天気・降水確率の区域コード",
  "temperatureAreaCode": "気温の予報地点コード"
}
```

実装時は気象庁が公開する区域定義を参照し、コードを推測で記載しない。徳島県、高知県、愛媛県、香川県にある全88札所が必ず1つの予報区域へ割り当てられていることをテストする。

同一県内でも東部・西部、北部・南部などで予報区域が異なるため、都道府県だけを見て一括設定しない。

## 5. サーバー側の取得処理

### 5.1 取得の流れ

1. 気象庁のPULL型配信フィードから対象電文の更新情報を確認する。
2. 必要な `VPFD51` または `VPFW50` 電文を取得する。
3. XMLを解析し、発表元、発表時刻、対象日・時間帯、区域コードごとの予報値へ変換する。
4. アプリ内部で扱いやすい正規化形式にしてキャッシュする。
5. `/weather-proxy` から札所・日付・到着予定時刻に対応する値だけを返す。

既存URLとの互換性を保つため、エンドポイント名 `/weather-proxy` と `points` の入力形式は維持してよい。ただしレスポンスには情報源と予報時間帯を追加する。

### 5.2 正規化レスポンス

```json
{
  "available": true,
  "source": "JMA",
  "publishedAt": "2026-08-20T11:00:00+09:00",
  "forecastAreaName": "徳島県北部",
  "weatherCode": "100",
  "weatherText": "晴れ",
  "temperature": {
    "maxC": 32,
    "minC": 25
  },
  "precipitationProbability": 20,
  "precipitationPeriod": "12:00-18:00",
  "isDailyForecast": false
}
```

気象庁電文に存在しない項目は `null` とし、0として補完しない。特に降水確率が欠落している場合、0%と表示してはならない。

### 5.3 キャッシュ

- 気象庁フィードの確認間隔は10分以上とする。
- 予報電文は発表元・データ種類・発表時刻をキーとしてキャッシュする。
- 同一電文を札所ごとに再取得しない。
- 正常取得した予報は次の発表を取得するまで利用できる。
- 取得失敗時は連続再試行せず、5分以上あけて再試行する。
- アプリのプロセス再起動直後も一斉アクセスにならないよう、可能であれば永続キャッシュを使用する。

Open-Meteo用に存在する「緯度・経度・日付・時刻ごとの30分キャッシュ」は廃止し、気象庁の電文単位キャッシュへ置き換える。

## 6. 画面表示

### 6.1 時間帯別予報

```text
☀️ 最高32℃ / 最低25℃  ☔20%
12〜18時・気象庁発表
```

- 天気アイコンは気象庁の天気コードから変換する。
- 天気名称も取得した気象庁の内容を使用する。
- 降水確率には対象時間帯を必ず併記する。
- 「到着予定時刻の降水確率」と誤認させず、「到着時刻を含む予報時間帯の降水確率」であることが分かる表示にする。

### 6.2 日別予報

```text
🌤️ 最高30℃ / 最低23℃  ☔40%
日別予報・気象庁発表
```

時間帯別の値ではない場合、「日別予報」と明記する。

### 6.3 欠損・エラー

- 一部の項目だけ存在する場合、存在する項目だけ表示する。
- 降水確率がない場合、`☔0%` ではなく降水確率部分を非表示にする。
- すべて取得できない場合、天気チップを非表示にするか「予報を取得できません」と表示する。
- 取得失敗をユーザー操作の失敗として扱わず、ルート計算自体は正常に表示する。

### 6.4 多言語対応

日本語、英語、韓国語、中国語（簡体・繁体）、ドイツ語、ポルトガル語について、少なくとも次の文言を追加する。

- 気象庁発表
- 時間帯別予報
- 日別予報
- 予報を取得できません
- 最高気温
- 最低気温

固有の天気文言を翻訳する場合は気象庁コードをアプリ内の翻訳キーへ変換し、取得した日本語文字列の機械的な部分一致だけに依存しない。

## 7. Open-Meteoの廃止範囲

- `api.open-meteo.com` へのリクエストを削除する。
- `precipitation_probability`、`relative_humidity_2m` などOpen-Meteo固有の処理を削除する。
- 湿度表示を削除する。
- Open-Meteoの日次フォールバック処理を削除する。
- Open-Meteoを前提としたテストデータと説明文を気象庁仕様へ更新する。
- Open-MeteoのURLや名称が実行コードに残っていないことを自動テストまたは検索で確認する。

## 8. テスト要件

### 8.1 XML解析

- `VPFD51`から天気、気温、時間帯別降水確率を正しく取得できる。
- `VPFW50`から日別の天気、最高・最低気温、降水確率を正しく取得できる。
- 名前空間付きXMLを正しく解析できる。
- 要素の順番が変わっても、区域コードと時刻を基準に対応付けできる。
- 欠損値を0へ変換しない。

### 8.2 予報選択

- 到着予定時刻が属する降水確率の時間帯を選択する。
- 日をまたぐルートで翌日の予報を選択する。
- 週間予報では日付に対応する日別予報を選択する。
- 予報期間外では `available:false` を返す。

### 8.3 区域対応

- 1番から88番まで全札所に区域設定がある。
- 登録されていない区域コードを検出した場合、起動時またはテスト時に失敗する。

### 8.4 キャッシュ・障害対応

- 同じ電文を複数札所から要求しても外部取得は1回だけになる。
- 気象庁が一時的に応答しなくてもルート計算は失敗しない。
- 古い予報を表示する場合は発表時刻を保持し、許容期限を超えたものは表示しない。

### 8.5 画面

- 降水確率と対象時間帯が一緒に表示される。
- 湿度が表示されない。
- 多言語でレイアウトが崩れない。
- 小さい実機画面でも寺名や納経時間と重ならない。

## 9. 完了条件

- 全88札所で気象庁の予報区域が設定されている。
- 天気、最高・最低気温、降水確率が気象庁電文から表示される。
- 降水確率の対象時間帯または日別予報であることが画面上で判別できる。
- 湿度表示が削除されている。
- Open-Meteoへの通信が発生しない。
- 気象庁の取得障害がルート計算に影響しない。
- 型チェックと全自動テストが成功する。
- Android実機で、ルート計算、日またぎ、予報なし、通信失敗の各ケースを確認する。

## 10. 実装上の注意

気象庁の公開データは無料で取得できるが、商用APIのSLAを持つサービスではない。メンテナンスや配信遅延の可能性を考慮し、キャッシュと障害時処理を必須とする。

また、気象庁の降水確率は札所の一点予報ではなく予報区域の値である。画面では「霊山寺の降水確率」のような表現を避け、「徳島県北部・12〜18時」のように区域と時間帯を明示する。
