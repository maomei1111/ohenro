# 気象庁移行後の品質改善仕様

## 1. 目的

気象庁天気予報への移行後に確認された取得・表示上の問題と、見どころページから戻った際の位置復元、継続的な品質確認を改善する。

本仕様の対象は次の5項目とする。

1. 3～7日先の週間予報を安定して取得する
2. 見どころページから、押した札所の位置へ戻る
3. スマートフォン上で予報区域・対象時間帯・情報源を確認できるようにする
4. 天気アイコンだけでなく天気文言も表示する
5. GitHub Actionsによる自動チェックと旧仕様書の整理

コンパス機能は別対応中のため、本仕様の対象外とする。御朱印の位置判定設定も変更しない。

## 2. 優先順位

| 優先度 | 対応 |
|---|---|
| P1 | 気象庁週間予報フィードの取得修正 |
| P1 | 見どころから戻った位置の復元 |
| P2 | 天気の補足情報を画面上へ表示 |
| P2 | 天気文言の表示 |
| P2 | GitHub Actionsの追加 |
| P3 | Open-Meteoを前提とする旧仕様記載の整理 |

## 3. 気象庁週間予報フィード

### 3.1 現状の問題

`src/jma-weather.ts`は、気象庁の短時間版フィードである次のURLだけを参照している。

```text
https://www.data.jma.go.jp/developer/xml/feed/regular.xml
```

短時間版フィードには直近の電文しか残らないため、1日2回発表される週間予報`VPFW50`が含まれない時間帯がある。アプリやRailwayがその時間帯に起動すると、3～7日先の予報電文を一度も取得できず、週間予報が表示されない。

### 3.2 修正方針

長期間版フィードを使用する。

```text
https://www.data.jma.go.jp/developer/xml/feed/regular_l.xml
```

実装は次のいずれかとする。

- 推奨: `VPFD51`と`VPFW50`の両方を`regular_l.xml`から検索する
- 代替: 短期予報は`regular.xml`、週間予報は`regular_l.xml`から検索する

実装の単純さと起動時刻に左右されない安定性を優先し、両方を`regular_l.xml`から検索する方法を推奨する。

### 3.3 キャッシュ

- フィード確認間隔は現在と同じ10分以上を維持する。
- 同じ発表時刻の電文を再取得しない。
- `VPFD51`と`VPFW50`の電文キャッシュは分けて保持する。
- 気象庁への取得失敗後は5分以上あけて再試行する。
- 取得済み電文が24時間以内の場合は、一時的な通信失敗時に利用してよい。
- 24時間を超える古い予報は表示しない。

### 3.4 フィード解析

- Atomフィード内の`id`または`link href`から電文URLを取得する。
- `updated`が最も新しい対象電文を選択する。
- URL文字列の並び順だけに依存せず、データ種類コードと発表官署コードを明示的に照合する。
- `regular_l.xml`が大きいため、1リクエスト内で札所ごとに繰り返し解析しない。

### 3.5 テスト

- 短時間版フィードに`VPFW50`が存在しないケースを再現する。
- 長期間版フィードから`VPFW50`を取得できることを確認する。
- 3日先、6日先、7日先の予報を取得できることを確認する。
- 8日先は`available:false`になることを確認する。
- サーバー起動時刻にかかわらず週間予報を取得できることを確認する。
- 同一県の複数札所を要求しても、フィードと同一電文の取得が1回に集約されることを確認する。

## 4. 見どころページから戻った位置の復元

### 4.1 現状の問題

見どころページから戻るとルート結果そのものは復元されるが、スクロール位置を保存していないため、ルート結果の先頭へ戻る。

ユーザーが35番札所の「由来・見どころを見る」を押した場合は、戻る操作後も35番札所付近へ戻る必要がある。

### 4.2 保存する情報

見どころリンクを押した時点で、`sessionStorage`または`history.state`へ次を保存する。

```json
{
  "templeNo": 35,
  "scrollY": 2840,
  "routeKey": "1-40-2026-08-21-09:00-ja"
}
```

- `templeNo`: 押した札所番号
- `scrollY`: リンク押下時のスクロール位置。札所要素が見つからない場合の予備値
- `routeKey`: 出発札所、到着札所、日付、時刻、言語を組み合わせた識別子

別のルート結果へ誤ってスクロールしないよう、現在のルート条件と`routeKey`が一致する場合だけ復元する。

### 4.3 ルート項目の識別

各ルート項目へ安定したIDを付ける。

```html
<div class="stop" id="route-stop-35">
```

見どころリンクには札所番号を保存するクリック処理を追加する。

JavaScriptを無効化した場合でも通常遷移できるよう、`href`はそのまま維持する。

### 4.4 戻り位置の復元タイミング

ページ読込直後ではなく、キャッシュされたルート結果の`renderResult()`完了後に復元する。

1. URLとキャッシュからルート条件・結果を復元する
2. `renderResult()`で札所一覧を描画する
3. 保存された`routeKey`が現在の条件と一致することを確認する
4. `route-stop-{templeNo}`を探す
5. 見つかった場合は`scrollIntoView({ block: 'center' })`で対象札所を表示する
6. 見つからない場合だけ`window.scrollTo(0, scrollY)`を使用する
7. 正常復元後、保存した戻り位置を削除する

下部ナビゲーションと対象札所が重ならないよう、札所要素に`scroll-margin-bottom`または適切な中央配置を指定する。

### 4.5 Android WebView

- Android側の戻る操作でWebView履歴へ戻った場合も同じ復元処理を通す。
- Android側だけでスクロール位置を管理せず、Web版と共通のJavaScript処理に集約する。
- 地図モーダル等が開いている場合は、既存のAndroid戻るブリッジによるモーダル終了を優先する。

### 4.6 テスト

- 1番、途中の札所、最終札所から見どころを開き、同じ札所へ戻る。
- 順打ち・逆打ちの両方で確認する。
- 日本語以外の言語でも同じ位置へ戻る。
- ルート条件が変わった場合は古い位置を復元しない。
- 保存データが壊れていてもページ上部で正常表示される。
- Android実機の戻る操作で確認する。

## 5. 天気表示の改善

### 5.1 現状の問題

現在、通常画面に表示されるのは天気アイコン、最高・最低気温、降水確率だけである。

予報区域、降水確率の対象時間帯、情報源はHTMLの`title`属性に設定されているが、スマートフォンではマウスホバーできないため、利用者がほぼ確認できない。

また、気象庁から取得した`weatherText`を保持しているが、画面には「晴れ」「くもり」「雨」などの文言を表示していない。

### 5.2 表示内容

天気チップを2行構成にする。

```text
☀️ 晴れ　最高32℃ / 最低25℃　☔20%
徳島県北部・12〜18時・気象庁発表
```

週間予報の場合は次のように表示する。

```text
🌤️ 晴れ時々くもり　最高30℃ / 最低23℃　☔40%
徳島県・日別予報・気象庁発表
```

### 5.3 表示ルール

- `weatherText`が存在する場合、アイコンの直後へ表示する。
- 予報区域を常に画面上へ表示する。
- 短期予報では降水確率の対象時間帯を常に表示する。
- 週間予報では「日別予報」と表示する。
- 「気象庁発表」を常に表示する。
- `title`属性は補助情報として残してよいが、必要な情報を`title`だけに置かない。
- 欠損値を0として表示しない。
- 天気文言だけ取得できた場合も表示する。
- 気温だけ取得できた場合も表示する。
- すべて取得できない場合は「予報を取得できません」と表示する。

### 5.4 長い天気文言

気象庁の天気文言には「くもり時々晴れ所により昼過ぎから雨」など長い内容が含まれる。

- 1行への強制固定を行わず折り返しを許可する。
- 寺名、札所番号、納経時間と重ならないレイアウトにする。
- 360px幅のAndroid実機相当で確認する。
- 極端に長い文言はCSSで2行まで表示し、詳細全文をアクセシブルな方法で確認できるようにする。

### 5.5 多言語

天気文言は日本語文字列をそのまま表示せず、可能な限り気象庁の天気コードから基本状態を翻訳する。

最低限、次を各対応言語へ追加する。

- 晴れ
- くもり
- 雨
- 雪
- 雷
- 霧
- 時々
- のち

複雑な予報文を完全翻訳できない場合、日本語以外では気象庁コードから生成した簡潔な状態を表示し、日本語だけ原文を表示する。

## 6. GitHub Actions

### 6.1 目的

ローカルで成功している型チェックと109件のテストを、プルリクエストごとに自動実行する。

### 6.2 ワークフロー

`.github/workflows/ci.yml`を追加し、次のタイミングで実行する。

- `main`向けプルリクエスト
- `main`へのpush

処理内容は次のとおり。

```yaml
- npm ci
- npm run typecheck
- npm test
```

- Node.jsのバージョンを明示的に固定する。
- npmキャッシュを有効化する。
- テスト失敗時はマージ前に確認できるようにする。
- 外部の気象庁ネットワークへ依存せず、XMLフィクスチャとモックで実行する。

## 7. 仕様書の整理

`docs/CSS_AND_SERVER_PROTECTION_SPEC.md`には、現在もOpen-Meteoを前提とした天気取得仕様が残っている。

次の記載を現在の実装に合わせて更新する。

- `/weather-proxy`の入力形式を`templeNo,date,time`へ変更
- Open-Meteoの日次・時間別APIに関する説明を削除
- 気象庁`VPFD51`と`VPFW50`の選択方法を記載
- 湿度の記載を削除
- 電文単位キャッシュと再試行間隔を記載
- 降水確率が区域・時間帯単位であることを記載

`docs/JMA_WEATHER_MIGRATION_SPEC.md`を正とし、重複する説明は参照リンクへ置き換えてもよい。

今回の修正後も次の既存機能が変わらないことを確認する。

- ルート計算
- 順打ち・逆打ち
- バス・徒歩区間表示
- 納経受付時間の注意表示

- スマートフォン上で天気文言、予報区域、時間帯または日別予報、気象庁発表を確認できる。
- Open-Meteoを前提とする旧仕様記載が整理されている。
- GitHub Actionsで型チェックと全テストが成功する。

- コンパスの別対応と競合していない。
