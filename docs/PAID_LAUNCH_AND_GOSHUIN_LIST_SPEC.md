# 100円有料公開・将来無料化および御朱印一覧改善仕様

## 1. 目的

「お遍路みちしるべ」を初回は100円の有料アプリとして公開し、将来「無料アプリ＋買い切りPro」へ変更する場合にも、初期の有料購入者が追加料金なしでPro機能を利用できるようにする。

あわせて、御朱印一覧カード左上の札所番号が御朱印画像を隠している表示を改善する。

## 2. 今回の決定事項

- 初回公開時のアプリ価格は100円とする（Google Play Consoleで設定）。
- 初回公開版は購入後に全機能を利用できるものとし、広告は表示しない。
- 将来無料化した場合、100円で購入した既存利用者には買い切りPro相当の権利を無償で付与する。
- 既存購入者に、無料化後あらためてPro購入を要求してはならない。
- 御朱印一覧の札所番号は、御朱印画像に重ならない位置へ移動する。

## 3. 将来無料化した場合の既存購入者保護

### 3.1 基本要件

- 有料公開期間中に正規購入した利用者を`legacy_paid_user`として扱う。
- `legacy_paid_user`には、無料化後のPro商品を購入済みと同等の権利を付与する。
- Pro権利はアプリの更新後も維持する。
- アプリの再起動、更新、端末再起動で権利を失わない。
- 可能な限り、再インストールおよび機種変更後も権利を復元できるようにする。
- オフライン時は最後に検証済みの権利を端末内へ安全にキャッシュし、一時的な通信失敗だけでProを解除しない。
- 払い戻し、不正購入または権利取消しが確認された場合にのみ権利を無効化する。

### 3.2 重要な制約

Google Play Billingで取得できるアプリ内商品の購入情報と、アプリ本体を100円で購入した履歴は同一ではない。無料化後にBilling Libraryだけを追加しても、過去の「有料アプリ本体の購入者」を確実に列挙できるとは限らない。

したがって、端末内の`SharedPreferences`だけで既存購入者を判定してはならない。端末データの削除や機種変更で権利を失うためである。また、アプリが有料だった日付だけで利用者を推測してはならない。

### 3.3 無料化前に必要な移行準備

無料化を決定した場合は、価格変更より先に次を実施する。

1. 有料版のまま「Pro移行準備版」を公開する。
2. Google Playから正規取得されたアプリであることを確認する方法について技術検証を行う。
3. 検証済み利用者へ、サーバー側で永続的な`legacy_paid`権利を登録する。
4. 利用者が登録状態を確認できる「購入者特典を登録済み」表示を設定画面へ追加する。
5. 機種変更に備え、Googleアカウント等への安全な関連付け、または引継ぎコードによる復元手段を用意する。
6. 一定期間、移行準備版への更新を案内する。
7. 再インストール・機種変更を含む復元試験が成功してから、Google Play Consoleでアプリを無料へ変更する。

正規購入者を安定して識別・復元できる方法が確立できない場合は、無料化を実行しない。やむを得ず無料化する場合は、購入記録を提示した利用者へPro用プロモーションコード等を発行する救済窓口を用意する。

### 3.4 無料化後の権利判定

Proの利用可否は、次のいずれかを満たす場合に有効とする。

- `legacy_paid`：100円の有料公開期間中の購入者として登録済み
- `pro_one_time`：無料化後の買い切りProをGoogle Play Billingで購入済み

画面や機能側では購入経路を意識せず、共通の`hasProEntitlement`だけを参照する。

```text
hasProEntitlement = legacy_paid || pro_one_time
```

権利情報には少なくとも、権利種別、状態、登録日時、最終検証日時を保持する。購入トークンなどの機密情報をブラウザー側の`localStorage`へ保存しない。

### 3.5 無料化後の買い切りPro

- Proは繰り返し購入しない「非消費型の1回限りの商品」とする。
- Androidアプリ内でデジタル機能を販売する場合はGoogle Play Billingを使用する。
- 購入完了だけで即時開放せず、購入状態が`PURCHASED`であることを確認する。
- 購入情報は可能な限りRailway上のバックエンドで検証する。
- 購入承認処理を期限内に行い、自動返金を防止する。
- 「購入を復元」操作を設定画面に用意する。
- `legacy_paid`利用者にはPro購入ボタンを出さず、「初期購入者特典：Pro利用中」と表示する。

### 3.6 受け入れ条件

- [ ] 有料版購入者が無料化後も追加決済なしでPro機能を利用できる
- [ ] 有料版購入者にはPro商品の購入導線が表示されない
- [ ] 新規無料利用者には無料機能とPro機能が正しく分かれて表示される
- [ ] 新規無料利用者がProを購入すると、アプリ再起動後も利用できる
- [ ] 購入復元後にPro機能を利用できる
- [ ] 一時的にオフラインでも、直近で検証済みの利用者は突然Proを失わない
- [ ] 再インストール・機種変更の復元方法を実機で確認している
- [ ] 既存購入者を確実に識別できない状態では無料化しない

## 4. 御朱印一覧の札所番号表示改善

### 4.1 現状

`#viewZukan .zukan-card .zukan-no`がカード左上へ絶対配置され、幅38px以上、高さ34px、文字サイズ16pxで御朱印画像の上に重なっている。このため、画像左上にある印や文字が番号で隠れる。

### 4.2 改善方針

- 札所番号を御朱印画像上へ重ねない。
- 番号はカード下部の札所名情報欄へ移し、札所名の左側に表示する。
- 表記は全札所でゼロ埋めした2桁（`01`～`88`）に統一する。
- 番号は小さな朱色のラベルとし、札所名より目立たせない。
- 訪問前カードでも位置と寸法は同一とし、色だけ落ち着いた灰色へ変更する。
- 御朱印画像は上端から欠けずに表示し、画像固有の印・文字・日付欄を番号で隠さない。
- 日本語、英語、韓国語、中国語、ドイツ語、スペイン語で札所名が変わってもレイアウトが崩れないようにする。

推奨する情報欄の構造は次のとおり。

```html
<div class="zukan-info">
  <div class="zukan-name-row">
    <span class="zukan-no">01</span>
    <span class="zukan-name">霊山寺</span>
    <span class="zukan-card-date">訪問日</span>
  </div>
</div>
```

番号の目安は、文字サイズ11～12px、最小幅24～28px、高さ20～22pxとする。端末のフォント拡大設定でも、番号が御朱印画像側へはみ出さないようにする。

### 4.3 実装対象

- `src/public/js/settings.js`
  - `zukan-no`を画像領域の前ではなく`zukan-name-row`内へ移動する
  - `temple.no`を`01`～`88`の2桁表記で出力する
- `src/public/css/goshuin.css`
  - `zukan-no`の絶対配置を廃止する
  - 情報欄内の小型ラベルとしてスタイルを調整する
  - 札所名と訪問日の省略・折返し優先順位を調整する
- `src/public/css/themes.css`
  - ダークテーマでも番号と札所名のコントラストを確保する

### 4.4 受け入れ条件

- [ ] 01～88すべてのカードで番号が御朱印画像に重ならない
- [ ] 画像左上の印や文字が隠れない
- [ ] 番号が`01`～`88`の2桁で統一される
- [ ] 360px程度のスマートフォン幅でも番号・札所名・訪問日が重ならない
- [ ] 日本語以外の長い札所名でもカード外へはみ出さない
- [ ] 未訪問、訪問済み、画像読込失敗の各状態でレイアウトが崩れない
- [ ] ライトテーマとダークテーマの両方で判読できる
- [ ] Android実機とエミュレーターで同じ位置に表示される

## 5. テスト方針

### 5.1 課金移行

- 有料購入者、無料新規利用者、Pro購入者の3種類で権利判定をテストする。
- 正常購入、保留中、キャンセル、払い戻し、オフライン、再起動を確認する。
- アプリ更新、データ削除、再インストール、別端末への機種変更を確認する。
- 本番商品ではなく、Google Playのライセンステスターと内部テストトラックを使用する。

### 5.2 御朱印一覧

- 01、09、10、88の番号を確認する。
- 未訪問、訪問済み、長い参拝日、画像なしを確認する。
- 対応する全言語、ライト・ダークテーマ、端末フォント標準・拡大を確認する。
- 画面幅360px、一般的なスマートフォン幅、タブレット幅を確認する。

## 6. 今回は実施しないこと

- この仕様書追加と同時には、アプリ課金を実装しない。
- この仕様書追加と同時には、アプリを無料へ変更しない。
- この仕様書追加と同時には、御朱印一覧のHTML/CSSを変更しない。
- 広告SDKは導入しない。
